Do not deploy from this page

These buttons are a reference copy, not a release. factfind360.com is now built from github.com/RickyRampersad/fact-find-analyzer, and a file dragged onto Netlify by hand would overwrite the site and put it out of step with the repository. Changes go through git — the steps are below.

What is repaired

Five things

Replacement — a note, not a lecture

Guardian policies only. When a client is replacing one, the advisor sees a single line — “Replacing an existing Guardian policy. Complete and sign the disclosure form at the back of the pack.” No citations, no stacked warnings, and it does not block submission.

The Central Bank disclosure form

Did not exist in the live build. It now renders automatically whenever a replacement is detected, prefilled from the fact find — insurer, year, type, sums, premiums — with the verbatim caps warning, the nineteen-row comparison, the cost table and three signature blocks.

Guardian’s page five stops at four rows

Recommendations five and six were overrunning the printed form. Page five now hard-stops at four and prints a line saying where the rest are; the overflow is set out in full on the addendum with priority, need, plan, amount, premium and reason.

The reason that would not save

Premchand’s bug. dec{N}Reason had no schema entry, so every reason an advisor typed was silently dropped on the way to the sheet — and the checks then re-raised “no reason given” on a case that had just been fixed. The reason is the compliance artefact; it now has a column and it saves.

Seventeen needs, and the addendum that carries them

Seventeen rules read the fact find the advisor has already filled in and surface what nobody asked about — the business with no buy-sell, the mortgaged rental, the uninsured card, the child with nothing costed — each with the question that opens it. Four go on Guardian’s form; the rest go in the advisor’s bag as the next appointment.

Changing the form from here on

Four steps, in a browser

1

Open the file in the repository

github.com/RickyRampersad/fact-find-analyzer → ffproject.html → the pencil icon. That file is the live form; there is no build step and no copy to keep in step with it. Leave the name alone — it is lowercase because factfind360.com/ffproject is the address advisors already have, and renaming it moves that address.

2

Commit to a new branch, not the live one

At the bottom of the edit screen choose Create a new branch for this commit, give it a name, and open the pull request GitHub offers. The production branch is compliance-panel; committing straight to it publishes to advisors with nothing in between.

3

Netlify builds a preview by itself

Within a minute the pull request shows a Deploy Preview link — the whole site with your change on it, on its own address, touching nothing live. Open a real case on it: put a replacement through, print the pack, check the compliance panel.

4

Merge when the preview is right

Merging publishes it, and every advisor has the change on their next reload. If it turns out wrong, Deploys → the previous deploy → Publish deploy puts the site back in about thirty seconds, and you fix it in the repository.

Never drag a folder onto Netlify again

That is how this site was published until 23 August 2026, and a manual deploy replaces every file — anything missing from the folder is deleted. It is what removed walkthrough.html, insights.html, wall.html and the tour video that day. Two of those are not linked from the home page, so nothing on screen said they were gone. Git is the way in now.
