Updating the tracker's script

Ten minutes, once. You are copying one file into Google Apps Script, pressing deploy, and running one function. Nothing on this page can break the tracker or touch anybody's data — and there is a button at the bottom that tells you whether it worked.

Before you start You need to be signed in to Google as the person who owns the KPI workbook. If the Apps Script editor opens read-only, you are on the wrong account.

What you are doing

And why it is worth the ten minutes

The tracker's website was updated already — that part happens on its own. The script inside the Google workbook does not. It is still the old copy, and it is the reason submitting a block is slow at three o'clock and why people were being knocked out of the tracker.

The new copy does the same work in a third of the steps, and stops one person's submission holding everybody else's up.

The steps

Each one says what you should see when it has worked

1

Open the script

Open the KPI workbook in Google Sheets. In the menu: Extensions → Apps Script.

You should see: a code editor titled RRB KPI Tracker, with Code.gs at the top of the file list on the left.

The file is Code.gs In the repository this file is called KPI.gs; in the Apps Script project it is called Code.gs. Same file, two names. Intelligence.gs is the wall's data script and is pasted the same way, over its own file. The others — Reports.gs, KPI-Waiting.gs, KPI-Write.gs — are separate and must not be touched.
2

Get the new files — there are two

Open the tracker's code (goes into Code.gs) and the wall's data script (goes into Intelligence.gs), each in another tab. In each, click anywhere in the text, then press Ctrl + A and Ctrl + C (on a Mac, ⌘ A then ⌘ C).

Merging on GitHub does not do this The website updates itself when a change is merged. The script does not — it lives in Google's editor, and only a paste and a new version change it. On 8 September the wall's look updated on merge and its data stayed empty for the night, because the data script had not been pasted since the fix went in.

You should see: the whole page highlighted before you copy.

3

Replace what is there

Back in the Apps Script tab, click Code.gs in the list, click once inside the code, press Ctrl + A to select all of the old code, then Delete. The file should be completely empty before you paste. Then Ctrl + V, and the save icon (💾) or Ctrl + S.

Delete first. This is the one that goes wrong On 3 September the new code was pasted underneath the old instead of over it, leaving one file with both scripts in it — 5,729 lines where there should have been about 3,100. Everything looked saved and nothing changed. Emptying the file first makes that impossible.

Then the same for the second file: click Intelligence.gs in the list, select all, delete, paste the wall's data script, save.

You should see: the last line number about 4,873 in Code.gs and about 7,864 in Intelligence.gs. If either is roughly double that, the old code is still in there — select all, delete, paste again.

4

Deploy it

Top right: Deploy → Manage deployments. Click the pencil (✏️) on the deployment that is already there. Under Version, choose New version. Then Deploy.

Do not use "New deployment" That makes a second web address, and the tracker keeps talking to the old one — so nothing changes and it looks like the update failed. It must be Manage deployments → pencil → New version.

You should see: the same Deployment ID as before, ending …flDdg.

5

Switch the warm-up on

Still in the Apps Script tab. In the function dropdown at the top (it probably says doGet), choose installTriggers, then press Run.

This is what stops the tracker falling asleep. Google puts the script to sleep when nobody has used it for a while, and the next person to sign in waits half a minute while it wakes up. This wakes it every ten minutes during working hours so nobody has to.

It may ask permission Press Review permissions, choose the workbook owner's account, then Advanced → Go to … (unsafe) and Allow. It says unsafe because the script is not published on the Google store. It is our own file.

You should see: an execution log ending “Triggers installed. Warm-up every 10 minutes…”

6

Check it

Come back here and press the button below. It asks the workbook directly and tells you whether the new script is the one answering, and how fast it is now.

Did it work?

This asks the workbook which version of the script is running, and times it three times. Nothing is written or changed.

If something goes wrong

"Authorization required" Press Review permissions, choose the workbook owner's account, then Advanced → Go to … (unsafe) and Allow. It says unsafe because the script is not published on the Google store. It is our own file.
The check says the old script is still answering Almost always step 4 — New deployment was used instead of Manage deployments → pencil → New version. Go back and edit the existing deployment.
The check says the tracker is current but the wall's script is not Code.gs was pasted and versioned; Intelligence.gs was not — or was pasted from an older copy. Step 2 and 3 again for the second file only, then step 4. Every wall screen stays empty until then.
Red marks in the editor The paste went in on top of the old code rather than over it. Select all (Ctrl + A) in the editor, delete, then paste again.
Nothing here can lose data The script reads and writes the workbook, but this update does not change any row that is already there. If a step goes wrong, stop — the tracker carries on running the old script until a deployment succeeds.
